# 通用 agent 概念与锻造台插件的映射关系

《变形金刚：起源》里，钛师傅把变形齿轮交给奥利安一行时，说过变形齿轮可以被夺走，但夺不走他们胸口的火种和让世界变得更好的意志。
我们使用agent时，任务做不好，确实可以直接换一个更强的模型去解决。这种做法就如同 D-16 以热插拔的方式换上了震天尊的变形齿轮成为了威震天。电影中的这一幕也是我创建这个插件的叙事和哲学理论的契机。

这个叙事的初衷并不是把 dsh 的哲学体系强行往变形金刚的世界观上面去靠，用世界观中的词汇去比喻 dsh 生态的组件是手段而不是目的。
我尝试从我喜欢的世界观中寻找创作灵感，在尽量不侵入 dsh 原生环境的前提下开发新功能。

这张映射词典献给同样对两者都感兴趣的，我的同好~

| 锻造台意象 | dsh 概念 | 说明 |
|---|---|---|
| 变形齿轮（Cog） | LLM 型号 | 如同变形金刚换齿轮就可以立刻变强，换个推理更强的模型确实可以立刻解决复杂问题。但这不符合 agent engineering 的美学，咱不是基模算法工程师|
| 火种（Spark） | preset | 火种是preset的超集。在 README 中我枚举了两者的区别  |
| 火种源（AllSpark） | 上下文理论框架 | 和记忆策略一样，上下文策略是主观选择。所以我们支持管理多个火种源和跨火种源家族的实例协作 |
| 量产机型 | 火种锻造出的会话实例 | 对应赛博坦星量产npc。除了名字和记忆不同，共享意识洪流和使命 |
| 神铸 | 基于preset创建会话 | 变形金刚的诞生意味着一个基于图纸创建但是此刻开始独立生长的灵魂和记忆 |
| 领袖模块 | 会话的召集权限 | 领袖能感知同类，召集同类，指派任务，复活休眠的同类（和真人电影对上了） |
| 议事厅 | 项目档案 | 方法写在 system prompt, 文档不注入上下文仅作为知识资产 |

## 为什么在 0.3 阶段沿用 DSH 的原生 loop

DSH 原生 loop 正在快速迭代中，为避免无效开发，今后不会将替代性 loop 插件纳入火种配置。

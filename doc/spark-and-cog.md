# 火种、齿轮与会话

《变形金刚：起源》里，钛师傅把变形齿轮交给奥利安一行时，说起了火种赋予他们让世界变得更好的意志。锻造台借用了火种和齿轮这两个名字。一次代码审查进行到一半，换上更强的模型，审查者或许能看出先前漏掉的问题。它仍然是那个审查者，记得为什么要保住旧接口，也知道自己答应验证哪条回归用例。

| 作品中的意象 | 锻造台里的对应 | 在会话里意味着什么 |
|---|---|---|
| 变形齿轮（Cog） | LLM 型号 | 火种可以预选提供方、模型及推理等级。用户也可以在 DSH 里换模型，同一段会话继续。 |
| 火种（Spark） | 赋予会话身份的模板 | Persona 定义角色怎样做事，初始 soul 写下它应该记住什么。选定的工具、Skills、协作权限和用量预算决定它可以如何行动。 |
| 火种源（AllSpark） | 体现同一套做事原则的一组火种 | 一个团队可以从同一火种源锻造开发者和审查者。两者共享对兼容性的重视，各自有适合职责的配置。 |
| 一个诞生的赛博坦人 | 一枚火种锻造出的具体会话 | 同一模板能产生多个成员。每个成员有自己的会话历史和 soul，锻造时还可为它单独写下使命。 |
| 火种赋予机械生命的行动能力 | DSH 的 agent loop | 会话能根据模型的判断调用工具，读到结果，再决定下一步。这是每个锻造会话从宿主获得的能力。 |

## 为什么在 0.3 阶段沿用 DSH 的原生 loop

2026-11-25。锻造台把 loop 视为火种与生俱来的行动能力。工程上，这份能力由 DSH 提供。比如审查火种可以把单轮最后一步留给答复。到了那一步，锻造台通过宿主的工具守卫拒绝新的工具调用。决定是否进入下一步、发出模型请求和记录结果仍由 DSH 调度。[Energon 用量设置](handbook.md#energon-用量设置) · [DSH 原生 loop（0.2.2-rc.5）](https://cdn.jsdelivr.net/npm/@deepseek-ai/dsh-agent-loop@0.2.2-rc.5/README.md)

在锻造台 0.3 阶段，我们把精力放在“这个会话带着什么开始工作”。DSH 仍在快速迭代，沿用宿主的执行方式，锻造会话也能受益于上游对调度和恢复的改进。自行维护另一套驱动，则要跟进同一批变化。如果将来某类火种遇到原生扩展接口无法解决的具体问题，再用那个场景重新评估这项取舍。
